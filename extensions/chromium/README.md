# Cross Dynamic Island browser extension

Microsoft Edge and Chrome 116+ are supported. The extension shares media metadata, playback controls and, where the website permits it, the video element's own stream. It never captures the screen or browser tab. Audio stays in the original player.

1. Run Cross Dynamic Island once. The app registers its Native Messaging helper for the current Windows user. The NSIS installer also registers it.
2. In Settings → Music choose **Set up Edge** or **Set up Chrome**. This opens the extension folder and the browser's Extensions page.
3. Enable **Developer mode**, choose **Load unpacked**, and select the extension folder.
4. Connection is automatic. No code is needed. Existing HTTPS tabs receive the media scripts on installation; refresh old tabs once when upgrading from an earlier development version.
5. Start a video and expand the island. Live video connects automatically. The expand button beside the playback controls fills the expanded island with video. Controls and the title stay visible while the pointer is over the island, then fade 300ms after the pointer leaves. Re-entering cancels the hide timer. The lock button keeps the island open after outside clicks or pointer leave. Volume adjusts the original browser player when it exposes a volume control. The native window remains 340×190. Esc leaves this view.

In the extension popup, **Automatic video** disables or enables video, **Retry video** retries a restricted or stale player, and **Disconnect** stops the integration. CaptureStream cannot expose every cross-origin or DRM-protected source. Those players fall back to artwork and media controls. Access restrictions are respected. Video tracks can arrive asynchronously; the integration waits for them before negotiation.

SoundCloud volume uses the site's vertical slider, including its delayed hover expansion and mute state. Spotify seeking uses the site's range input or custom timeline when no MediaSession seek action is available, including when its audio element cannot seek. Both controls are available through the page-world player and the isolated DOM fallback. Failed or ignored website actions are rejected rather than acknowledged as successful.

The extension requests HTTPS access for detecting media elements. Only the current player metadata is reported. Spotify Web also reports its MediaSession metadata, playback actions and timeline when no audio element or matching miniplayer markup is available. SoundCloud can seek through its visible timeline without an audio element; a seek is acknowledged only after the timeline updates. Seeking remains disabled when no supported timeline or media action is available. The Native Messaging helper supplies a credential to the trusted worker; the credential is never shown in the popup or sent to page scripts. Metadata and signalling use an authenticated server on `127.0.0.1:43191`. Video uses WebRTC with host candidates and no STUN/TURN service. Only video tracks are forwarded. Encoding pauses when the island is collapsed or another page is selected. Changing the source, closing a tab or disabling video releases its stream.

For development, load C:\cross-di\extensions\chromium directly and reload the extension after changing its scripts. If Edge was pointed at src-tauri/target/release/browser-extension, update that bundled copy too. After upgrading to 0.4.2, reload the extension and refresh Spotify/SoundCloud tabs once so their MediaSession actions and position updates can be observed from page startup. The public manifest key keeps the extension ID stable. When upgrading from version 0.1, remove the old unpacked extension and load this folder again once.

For store distribution, publish the extension and update `extensions/browser-config.json` with the real store extension ID before rebuilding the app. There is no store listing yet; development installation still uses Load unpacked. The installer bundles this folder. No signing private key is stored in the repository.
